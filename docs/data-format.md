# Формат данных сервиса бронирования аудиторий

**Версия:** 1.0
**Основание:** PRODUCT.md, R5
**Связанное issue:** #6

## 1. Назначение

Документ описывает поля записи о бронировании аудитории: типы, единицы измерения,
допустимые значения и пример корректной записи. Предназначен для новых участников
команды, тестировщиков и авторов отчётов.

## 2. Таблица полей

| № | Поле | Тип | Обязательное | Единица / формат | Допустимые значения | Описание |
|---|------|-----|--------------|------------------|---------------------|----------|
| 1 | `id` | строка (UUID v4) | да | `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` | уникальный | Идентификатор брони |
| 2 | `room_id` | строка | да | `room-<номер>` | из справочника аудиторий | Идентификатор аудитории |
| 3 | `owner` | строка | да | email | домен организации | Владелец брони |
| 4 | `date` | строка | да | ISO 8601: `YYYY-MM-DD` | календарная дата | Дата бронирования |
| 5 | `start_time` | строка | да | ISO 8601: `HH:MM` (24 ч) | 00:00–23:59 | Время начала |
| 6 | `end_time` | строка | да | ISO 8601: `HH:MM` (24 ч) | > `start_time` | Время окончания |
| 7 | `status` | строка | да | enum | `pending`, `confirmed`, `cancelled` | Статус брони |

**Пояснения:**
- **Время** — локальное время сервиса, без часового пояса.
- **Дата** — только календарная дата, время хранится отдельно.
- **Статусы:**
  - `pending` — заявка создана, ожидает подтверждения;
  - `confirmed` — бронь подтверждена;
  - `cancelled` — бронь отменена; запись сохраняется для истории.
- **Ограничения:** пересечение интервалов в одной аудитории не допускается.
- **Открытый вопрос:** нужно ли поле `created_at` — уточняется отдельно.

## 3. Пример корректной записи (JSON)

```json

  "date": "2026-10-06",
  "start_time": "09:30",
  "end_time": "11:00",
  "status": "confirmed"
}
